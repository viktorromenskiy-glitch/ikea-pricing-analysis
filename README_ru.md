# IKEA Saudi Arabia — предсказание цены и анализ ценообразования

*[English version available here](README.md)*

Полноценный проект по анализу данных на датасете [TidyTuesday IKEA](https://github.com/rfordatascience/tidytuesday/tree/master/data/2020/2020-11-03) (3 694 строки, 2 962 уникальных SKU, рынок Саудовской Аравии). Проект охватывает проверку статистических гипотез, инженерию признаков с явным контролем утечек данных, оптимизацию гиперпараметров и несколько независимых уровней интерпретации модели — сделан с нуля как учебный проект, затем доведён до продакшен-структуры через рефакторинг.

## Результаты коротко

| Метрика | Значение |
|---|---|
| Финальная модель | Random Forest + Optuna (байесовский поиск гиперпараметров) |
| R² на тесте | **0.8453** |
| R² (5-fold CV) | 0.8616 ± 0.0132 |
| MAE на тесте | 303.97 SR |
| Улучшение vs. наивный baseline (медиана цены) | +66.2% по MAE |
| vs. Random Forest без настройки | +3.7% (в пределах шума CV — см. раздел ниже) |
| Оценка влияния на выручку vs. медиана по категории | +35.3% |

**Главные драйверы цены** (SHAP и встроенная важность признаков согласуются): **ширина** товара (~29%), **объём** (~23%), длина описания, частотность дизайнера и категория.

## Чем этот проект отличается от типового «обучили модель — вывели R²»

- **Каждое решение по отбору признаков подтверждено двумя независимыми статистическими тестами**, а не одним рейтингом важности. Групповой Ablation Study (удаление целых коррелирующих групп, например всех габаритов разом) сочетается с точечным Bootstrap Ablation (удаление по одному признаку, 15 повторов бутстрапа, 95% доверительный интервал на эффект) — эти два метода информативно расходятся именно там, где признаки коллинеарны, и это расхождение задокументировано и объяснено, а не спрятано.
- **Утечка данных — не второстепенный вопрос, а отдельная линия проверок.** Реализованы три независимые проверки: корреляционная проверка `old_price` (структурная утечка через формулу скидки была поймана и исключена, хотя наивный порог по корреляции её бы пропустил), проверка признака `sellable_online` на близость к константе, и строгий расчёт «только на train» для любой статистики, зависящей от целевой переменной (`category_price_level`, `designer_freq`, `is_large_item` считаются исключительно на обучающей выборке).
- **Кэш гиперпараметров Optuna снабжён отпечатком (fingerprint)**, а не просто наивно кэшируется. Он автоматически признаётся устаревшим при изменении набора признаков или параметров поиска — устаревшие метрики не могут незаметно просочиться в отчёт после правки кода.
- **Три модели-кандидата честно соревнуются**: простое сравнение baseline-моделей, байесовский поиск Optuna и GridSearchCV — победитель выбирается по R² на тесте, и если побеждает самая простая модель (проверка по принципу бритвы Оккама), пайплайн говорит об этом прямо, а не всегда венчает самую сложную.

## Структура репозитория

Изначально пайплайн был одним скриптом на ~9 900 строк; после рефакторинга — 7 модулей, каждый независимо импортируется и тестируется:

```
ikea_main.py           # точка входа — оркестрирует весь пайплайн, финальный отчёт
ikea_core.py           # конфигурация, dataclass MLPipelineResult, логирование, кэш Optuna (с отпечатком)
ikea_data_prep.py      # загрузка данных, дедупликация, очистка дизайнеров/габаритов
ikea_eda.py            # разведочный анализ, проверки на утечку (sellable_online / old_price)
ikea_hypotheses.py     # 9 статистических гипотез (bootstrap, Mann-Whitney, Kruskal-Wallis)
ikea_model.py          # инженерия признаков, Optuna, GridSearchCV, Ablation Study
ikea_interpret.py      # SHAP, важность признаков, остатки, сравнение с baseline, влияние на выручку
```

Сама функция `run_ml_pipeline()` в `ikea_model.py` разбита на 4 приватные вспомогательные функции (`_prepare_and_compare_baseline`, `_run_hyperparameter_search`, `_select_best_model`, `_run_post_training_analysis`) вместо одной функции на 300+ строк — чистый рефакторинг, проверенный сверкой с исходным монолитом: результат идентичен вплоть до 4-го знака после запятой.

## Как запустить

```bash
pip install -r requirements.txt
python ikea_main.py
```

Опциональные флаги:
```bash
python ikea_main.py --rerun-optuna       # принудительно пересчитать поиск гиперпараметров, игнорируя кэш
python ikea_main.py --trials 20 --cv 3   # уменьшить число итераций/фолдов для быстрого локального прогона
```

Датасет скачивается автоматически из репозитория TidyTuesday на GitHub при первом запуске — вручную скачивать не нужно. Результаты (графики, CSV-отчёты, обученная модель, полный лог прогона) сохраняются соответственно в `plots_step/`, `reports_step/`, `models/` и `logs/`.

## Обзор методологии

1. **Подготовка данных** — дедупликация (3 694 → 2 962 уникальных SKU), заполнение пропусков в габаритах, нормализация имён дизайнеров.
2. **Проверка статистических гипотез** — 9 гипотез (например, «больший объём → выше цена», «товары от команд дизайнеров дороже», «премиальные материалы поднимают цену») проверены через Mann-Whitney U, Kruskal-Wallis и bootstrap-доверительные интервалы на разность медиан.
3. **Инженерия признаков с контролем утечек** — признаки на основе габаритов, NLP-признаки (длина/число слов описания, упоминания премиальных материалов), контекст категории; любой признак, зависящий от train/test-специфичной статистики, считается строго после разбиения выборки.
4. **Отбор модели** — сравнение 8 базовых моделей, затем Optuna (4 эксперимента, байесовский TPE-поиск) и GridSearchCV соревнуются между собой и с простым baseline.
5. **Интерпретация** — SHAP-значения, встроенная важность признаков, Partial Dependence Plots, анализ остатков (включая проверку на гетероскедастичность), bootstrap-доверительный интервал для итогового MAE.
6. **Валидация признаков** — групповой Ablation Study и точечный Bootstrap Ablation с 95% доверительными интервалами, результаты сверяются между собой.
7. **Бизнес-интерпретация** — оценка влияния на выручку при переходе от ценообразования по медиане категории к предсказаниям модели.

## Честные ограничения (задокументированы, а не скрыты)

- Модель показывает **систематическое занижение цены на премиальных товарах** (анализ остатков, верхний ценовой сегмент) и **гетероскедастичность остатков** (дисперсия ошибки растёт вместе с ценой) — это явно отмечено, а не замалчивается.
- Два признака (`category_price_level`, `is_large_item`) показали устойчиво отрицательный вклад по отдельности в обоих тестах (групповом и точечном), но быстрая проверка их совместного удаления показала небольшой отрицательный совокупный эффект — поэтому они сохранены в модели до более строгой bootstrap-проверки совместного удаления. Логика рассуждения и точные цифры задокументированы в выводе Ablation Study, а не решены молча в ту или иную сторону.
- Random Forest, настроенный через Optuna, превзошёл ненастроенный baseline всего на 0.011 по R², что **меньше стандартного отклонения кросс-валидации** — пайплайн явно помечает это как статистически незначимое улучшение, в соответствии с встроенной проверкой по принципу бритвы Оккама.

# IKEA Saudi Arabia — предсказание цены и анализ ценообразования

*[English version available here](README.md)*

Полноценный проект по анализу данных на датасете [TidyTuesday IKEA](https://github.com/rfordatascience/tidytuesday/tree/master/data/2020/2020-11-03) (3 694 строки, 2 962 уникальных SKU, рынок Саудовской Аравии). Проект охватывает проверку статистических гипотез, инженерию признаков с явным контролем утечек данных, оптимизацию гиперпараметров и несколько независимых уровней интерпретации модели — сделан с нуля как учебный проект, затем доведён до продакшен-структуры через рефакторинг.

**🔗 [Попробовать живое демо](https://ml-ikea-app-c69harkxgk4nroywbv9iz6.streamlit.app/)** — интерактивное Streamlit-приложение, предсказывающее цену по атрибутам товара; большинство признаков выводятся автоматически из описания и имени дизайнера ([исходный код демо](https://github.com/viktorromenskiy-glitch/ml-ikea-app)).

## Результаты коротко

| Метрика | Значение |
|---|---|
| Финальная модель | Random Forest + Optuna (байесовский поиск гиперпараметров) |
| R² на тесте | **0.8296** |
| R² (5-fold CV) | 0.8609 ± 0.0126 |
| MAE на тесте | 312.00 SR |
| Улучшение vs. наивный baseline (медиана цены) | +65.3% по MAE |
| vs. Random Forest без настройки | ненастроенный RF показал R² на **0.0076 выше** (0.8372 против 0.8296) — разница в пределах шума CV, честно указана, а не сглажена (см. раздел ниже) |
| Оценка влияния на выручку vs. медиана по категории | +34.4% |

**Главные драйверы цены** (SHAP и встроенная важность признаков согласуются): **ширина** товара (~42%), **высота** (~11%), **глубина** (~10%), длина описания и ценовой уровень категории.

## Чем этот проект отличается от типового «обучили модель — вывели R²»

- **Каждое решение по отбору признаков подтверждено двумя независимыми статистическими тестами**, а не одним рейтингом важности. Групповой Ablation Study (удаление целых коррелирующих групп, например всех габаритов разом) сочетается с точечным Bootstrap Ablation (удаление по одному признаку, **40 повторов** бутстрапа, 95% доверительный интервал на эффект). Более ранняя версия проекта использовала 15 повторов и дала ощутимо иной (неверный) вердикт по одному признаку — что из этого выяснилось про статистическую мощность, см. в разделе «Честные ограничения» ниже.
- **Утечка данных — не второстепенный вопрос, а отдельная линия проверок.** Реализованы три независимые проверки: корреляционная проверка `old_price` (структурная утечка через формулу скидки была поймана и исключена, хотя наивный порог по корреляции её бы пропустил), проверка признака `sellable_online` на близость к константе, и строгий расчёт «только на train» для любой статистики, зависящей от целевой переменной (`category_price_level` и `designer_freq` считаются исключительно на обучающей выборке; `is_large_item` считается так же, но больше не входит в признаки модели — см. ниже).
- **Кэш гиперпараметров Optuna снабжён отпечатком (fingerprint)**, а не просто наивно кэшируется. Он автоматически признаётся устаревшим при изменении набора признаков или параметров поиска — устаревшие метрики не могут незаметно просочиться в отчёт после правки кода. Именно этот механизм поймал устаревший кэш в процессе разработки и вынудил сделать честный пересчёт с нуля.
- **Три модели-кандидата честно соревнуются**: простое сравнение baseline-моделей, байесовский поиск Optuna и GridSearchCV — победитель выбирается по R² на тесте, и пайплайн прямо показывает сравнение с ненастроенным baseline, а не только выигрышную для себя картину.

## Структура репозитория

Изначально пайплайн был одним скриптом на ~9 900 строк; после рефакторинга — 7 модулей (~10 000 строк суммарно), каждый независимо импортируется и тестируется:

```
ikea_main.py           # точка входа — оркестрирует весь пайплайн, финальный отчёт
ikea_core.py           # конфигурация, dataclass MLPipelineResult, логирование, кэш Optuna (с отпечатком)
ikea_data_prep.py      # загрузка данных, дедупликация, очистка дизайнеров/габаритов
ikea_eda.py            # разведочный анализ, проверки на утечку (sellable_online / old_price)
ikea_hypotheses.py     # 9 статистических гипотез (bootstrap, Mann-Whitney, Kruskal-Wallis)
ikea_model.py          # инженерия признаков, Optuna, GridSearchCV, Ablation Study
ikea_interpret.py      # SHAP, важность признаков, остатки, сравнение с baseline, влияние на выручку
```

Сама функция `run_ml_pipeline()` в `ikea_model.py` разбита на 4 приватные вспомогательные функции (`_prepare_and_compare_baseline`, `_run_hyperparameter_search`, `_select_best_model`, `_run_post_training_analysis`) вместо одной функции на 300+ строк — чистый рефакторинг, проверенный сверкой с исходным монолитом: результат идентичен вплоть до 4-го знака после запятой.

## Как запустить

```bash
pip install -r requirements.txt
python ikea_main.py
```

Опциональные флаги:
```bash
python ikea_main.py --rerun-optuna       # принудительно пересчитать поиск гиперпараметров, игнорируя кэш
python ikea_main.py --trials 20 --cv 3   # уменьшить число итераций/фолдов для быстрого локального прогона
```

Датасет скачивается автоматически из репозитория TidyTuesday на GitHub при первом запуске — вручную скачивать не нужно. Результаты (графики, CSV-отчёты, обученная модель, полный лог прогона) сохраняются соответственно в `plots_step/`, `reports_step/`, `models/` и `logs/`.

## Обзор методологии

1. **Подготовка данных** — дедупликация (3 694 → 2 962 уникальных SKU), заполнение пропусков в габаритах, нормализация имён дизайнеров.
2. **Проверка статистических гипотез** — 9 гипотез (например, «больший объём → выше цена», «товары от команд дизайнеров дороже», «премиальные материалы поднимают цену») проверены через Mann-Whitney U, Kruskal-Wallis и bootstrap-доверительные интервалы на разность медиан. (Важно: «влияет ли объём на цену» здесь — самостоятельный, законный EDA/гипотезный вопрос, отдельный от того, должен ли `volume` быть признаком *модели*; см. ниже.)
3. **Инженерия признаков с контролем утечек** — признаки на основе габаритов, NLP-признаки (длина/число слов описания, упоминания премиальных материалов), контекст категории; любой признак, зависящий от train/test-специфичной статистики, считается строго после разбиения выборки.
4. **Отбор модели** — сравнение 8 базовых моделей, затем Optuna (4 эксперимента, байесовский TPE-поиск) и GridSearchCV соревнуются между собой и с простым baseline.
5. **Интерпретация** — SHAP-значения, встроенная важность признаков, Partial Dependence Plots, анализ остатков (включая проверку на гетероскедастичность), bootstrap-доверительный интервал для итогового MAE.
6. **Валидация признаков** — групповой Ablation Study и точечный Bootstrap Ablation с 95% доверительными интервалами, результаты сверяются между собой.
7. **Бизнес-интерпретация** — оценка влияния на выручку при переходе от ценообразования по медиане категории к предсказаниям модели.

## Честные ограничения (задокументированы, а не скрыты)

- Модель показывает **систематическое занижение цены на премиальных товарах** (анализ остатков, верхний ценовой сегмент: среднее смещение +299 SR) и **гетероскедастичность остатков** (дисперсия ошибки растёт ~в 150 раз от нижнего к верхнему ценовому квинтилю) — это явно отмечено, а не замалчивается.
- `volume` был исключён из признаков модели — опасение по мультиколлинеарности с `depth`/`height`/`width` (объём — их произведение) было отмечено ещё на раннем этапе. Вопрос прошёл три раунда проверки: при 15 повторах bootstrap-теста признак выглядел незначимым (шум); при 40 повторах, с теми же гиперпараметрами, вердикт сменился на «значим» (результат на 15 повторах оказался недостаточной статистической мощности — ошибка второго рода, а не настоящее «нет эффекта»); после устранения устаревшего кэша Optuna и честного пересчёта поиска гиперпараметров с нуля на актуальном наборе признаков, итоговый, окончательный вердикт на 40 повторах — `volume` слегка **вредит** модели (ΔR²=−0,0032). `is_large_item`, производный от `volume`, был исключён по той же причине. Удаление обоих признаков слегка **улучшило** R² на тесте (0,8271 → 0,8302 в сопоставимом сравнении) — то есть речь не о размене точности на чистоту признаков, а о настоящем улучшении, которое потребовало три раунда проверки, чтобы увидеть ясно. `category_price_level` тоже показал небольшой отрицательный эффект в части тестов, но с широким доверительным интервалом, пересекающим ноль, поэтому оставлен как пограничный случай, а не удалён на основании более слабых оснований.
- Random Forest, настроенный через Optuna, показал R² на тесте **немного ниже**, чем ненастроенный Random Forest (0,8296 против 0,8372, разница 0,0076 — меньше стандартного отклонения кросс-валидации 0,0126). Модели статистически неразличимы; настроенная через Optuna модель выбрана финальной потому, что она получена системным, воспроизводимым поиском, а не потому, что она однозначно превосходит простой baseline — пайплайн сообщает об этом честно, а не показывает только выгодное для сложной модели сравнение.
